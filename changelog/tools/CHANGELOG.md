# tools

## 1.0.0-beta.1

### Major Changes

- [#64](https://github.com/VinSpee/undertone/pull/64) [`aa63884`](https://github.com/VinSpee/undertone/commit/aa63884e0ac7a2ae6b154096d34d603299c4e793) Thanks [@VinSpee](https://github.com/VinSpee)! - Gamut can now be installed on a BlackBox that runs M-VAVE's official V22 or V23, with no downgrade, and M-VAVE's firmware can be put back the same way. One command on a Mac, `sudo python3 tools/uboot_install.py` (`make usb-install`), takes the pedal from its RECOVERY screen to the chip's USB boot state and writes only the app area, never the boot loader; it is a dry run until `--write` is added, and it saves a backup of the whole flash first. The route has worked on one real pedal; the single command has so far run against simulated pedals only. The earlier route, `tools/pd40_install.py --write`, could not finish on a real pedal and is now refused. The same command also accepts a pedal with the older layout (V16, V17, V20) and refuses every other one; on those pedals the installer page remains the usual way. The steps are in the rescue guide, under "Gamut on a BlackBox with V22 or V23". The rescue kit is now number 6, with its texts brought up to date.

### Minor Changes

- [#44](https://github.com/VinSpee/undertone/pull/44) [`719b004`](https://github.com/VinSpee/undertone/commit/719b004937bef925acc3cb881bbb41bf8b553563) Thanks [@VinSpee](https://github.com/VinSpee)! - The installer page now shows one card for each firmware of the release, so you choose which one to install, switch to the other, and switch back from the same page. The list comes from a catalog (`release.json`) that the build writes beside the packages.

- [#96](https://github.com/VinSpee/undertone/pull/96) [`6dfb8be`](https://github.com/VinSpee/undertone/commit/6dfb8be690f9637f6b61b4cd3c8c6b6e51d36528) Thanks [@VinSpee](https://github.com/VinSpee)! - Gamut gets ready for 48 kHz. A cabinet IR is now loaded at the pedal's own sample rate, and the pedal plays an IR made at the other rate resampled, so your saved IRs keep their sound when Gamut moves to 48 kHz; the editor's note on a NAM capture's sample rate now compares it with the pedal's. At 44.1 kHz the sound is unchanged. A firmware that runs at 48 kHz offers USB audio at 48 kHz only, and the simulated pedal's sound runs at 48 kHz.

- [#58](https://github.com/VinSpee/undertone/pull/58) [`6c92e81`](https://github.com/VinSpee/undertone/commit/6c92e8193262da2ecaee0a051dcabb110aade14e) Thanks [@VinSpee](https://github.com/VinSpee)! - The guitar firmware is now Gamut 1.0b1 (`PocketX_950`, `BlackBox_950`), formerly OpenPocket v43. Its boot screen shows Gamut, its editor and the installer call it Gamut with the version 1.0b1, and the site, the README and the documents use the new name. The sound and the controls are those of v43. The USB device name, the update loader's identity and the package names stay as they were, so this installer, the editor and the original OpenPocket project's installer all still find the pedal; that installer names it OpenPocket v50.

- [#62](https://github.com/VinSpee/undertone/pull/62) [`4cf1479`](https://github.com/VinSpee/undertone/commit/4cf147959482b3708935528e09f23e6d5fe55a3e) Thanks [@VinSpee](https://github.com/VinSpee)! - A BlackBox on M-VAVE's official V22 or V23 can now get Gamut without going back to V21: `tools/pd40_install.py` writes Gamut's app area through that boot loader's own recovery mode, which never touches the boot loader, and puts M-VAVE's V23 app back the same way. It is not yet tried on a real pedal, so the installer page still refuses such a pedal; the build now also writes each BlackBox package's app area as a file of its own (`BlackBox_950-v23.bin`) for it. The steps are in the rescue guide, under "Gamut on a BlackBox with V22 or V23".

- [#59](https://github.com/VinSpee/undertone/pull/59) [`f255102`](https://github.com/VinSpee/undertone/commit/f255102c5661b5072b98e454790ce9a1b714e7e4) Thanks [@VinSpee](https://github.com/VinSpee)! - A BlackBox on M-VAVE's V22 or V23 can now be read when it shows RECOVERY: a new read-only helper in the rescue kit, `tools/pd40_recovery.py`, reads what the pedal's recovery mode reports, also over the control endpoint when the bulk endpoint sends zeros as on a real V23 pedal, and watches what the pedal starts when the recovery mode ends. Its command to leave for the USB boot state stays behind an explicit flag, because whether it gets there is not known. It never writes to the pedal.

- [#61](https://github.com/VinSpee/undertone/pull/61) [`7171689`](https://github.com/VinSpee/undertone/commit/71716892d8c0c1d46c85187da5b4be0ba31fcec4) Thanks [@VinSpee](https://github.com/VinSpee)! - The recovery helper for a BlackBox on M-VAVE's V22 or V23, `tools/pd40_recovery.py`, now watches the USB devices after every probe and logs when the pedal leaves its recovery mode, counted from the last command sent and from the first access, and whether it comes back as the USB boot state or as the normal pedal. A new flag, `--accept-control-reply`, given with `--leave --accept-inferred`, lets its single leave command go out when the pedal answered the hello only over the control endpoint, as a real V23 pedal did. It still never writes to the pedal.

- [#93](https://github.com/VinSpee/undertone/pull/93) [`6c36c73`](https://github.com/VinSpee/undertone/commit/6c36c730b78ef4ec60ffb8f2eba97fdffb48313c) Thanks [@VinSpee](https://github.com/VinSpee)! - `tools/uboot_install.py --image FILE` installs any app image on a BlackBox through the chip's USB boot state, the same way as Gamut, on a pedal with M-VAVE's V22 or V23 or with the older layout. It refuses a file that is not whole 4 KiB sectors, does not fit the pedal's app area or carries a boot area; it warns when the boot loader would not start the image, prints the file's SHA-256, asks for a typed `yes` before `--write`, and prints the way back. The dry run now also lists the sectors a write would change. Two test builds, `rate-diag` and `rate48`, decide whether Gamut can run at 48 kHz; the installer offers them only through `?channel=rate-diag` and `?channel=rate48`, and the steps are in `docs/RATE48-TEST.md`. The rescue kit is now number 9.

- [#80](https://github.com/VinSpee/undertone/pull/80) [`0403149`](https://github.com/VinSpee/undertone/commit/0403149cd2e0088449b1344500d99f66cec2e75a) Thanks [@VinSpee](https://github.com/VinSpee)! - The rescue kit has one command, `undertone`: run it with no options and it walks you through fixing a pedal that will not start, putting Gamut on a pedal or checking a pedal, one short screen at a time, with a drawing of the buttons to hold, and it saves a copy of the pedal and asks before it writes anything. `undertone rescue`, `undertone install` and `undertone check` do the same as plain lines. They run the same rescue and install tools as before.

- [#89](https://github.com/VinSpee/undertone/pull/89) [`02da132`](https://github.com/VinSpee/undertone/commit/02da1323d1b0392cd94d0858b2838a5b4cb59726) Thanks [@VinSpee](https://github.com/VinSpee)! - undertone also comes as one program for Mac, Windows and Linux that needs nothing installed, not even Python: the Rescue card offers it beside the rescue kit, which stays the tested way until the program has been tried on a real pedal.

- [#92](https://github.com/VinSpee/undertone/pull/92) [`41f0356`](https://github.com/VinSpee/undertone/commit/41f03565aa2c4f66c9784e35fa0c052b4edbdddd) Thanks [@VinSpee](https://github.com/VinSpee)! - The one-program undertone now installs an app image of your own, such as a test build or firmware built on Undertone: `undertone install --gamut FILE`, or "a file of my own" in its screens.
